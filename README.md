## 为什么需要 SafeModelGateway？

ChatGPT、Claude、DeepSeek 已经深入企业的研发、运营、客服、市场等各个环节。但随之而来的是巨大的数据安全风险：

> - 员工把**客户名单、财务报表**直接粘贴给大模型提问
> - **源代码、密钥（API Key、数据库密码）** 被发送到外部模型平台
> - 无法知道**谁、在什么时候、用了哪个模型、发了什么内容**
> - 各业务线各自采购模型 API，成本失控、无人管控

**SafeModelGateway 在企业和所有大模型之间加了一道安全闸门**：业务系统照常调用 OpenAI 兼容接口，网关在中间完成敏感信息识别、脱敏、拦截、审计和配额管控 —— 体验不变，数据不漏。

## 核心能力

### 🛡️ 数据防泄露（DLP）
- **敏感信息识别**：内置规则引擎，开箱即用地识别手机号、身份证号、银行卡号、邮箱、API Key、数据库连接串、内网 IP、源代码片段等
- **动态脱敏**：命中敏感信息后自动替换为 `[PHONE]`、`[ID_CARD]` 等占位符，请求照常完成，数据不出企业
- **硬拦截**：对高危内容（如完整密钥、大批量客户数据）支持直接阻断并返回告警
- **响应侧过滤**：不仅管住出站请求，也过滤模型返回内容，防止幻觉生成的敏感信息回流

### 🔍 全链路审计
- 记录每一次调用的**用户、模型、时间、Token 用量、命中规则、脱敏/拦截详情**
- 敏感事件实时告警（Webhook / 邮件 / 钉钉 / 飞书）
- 审计日志留存，满足等保、ISO 27001、数据安全法等合规要求

### 🚦 访问与配额管控
- 按用户 / 部门 / 应用维度分配可用模型与额度
- Token 级计费与配额限制，防止成本失控
- API Key 全生命周期管理，离职即吊销

### 🔌 继承 one-api 全部能力
- 统一接入 OpenAI / Claude / Gemini / 文心 / 通义 / DeepSeek / 智谱 / Ollama 等主流模型
- OpenAI 兼容接口，业务代码**零改造**接入
- 负载均衡、故障自动切换、渠道管理
